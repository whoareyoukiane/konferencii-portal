# Практика 4. Подсистема безопасности

Выполнил Котлов Арсений Михайлович. Изменения в папке `portal`.

## Что сделано

| Пункт задания | Как сделано | Где |
|---|---|---|
| Хеширование паролей | `password_hash` при регистрации, `password_verify` при входе. Старые пароли пересчитала миграция `002_password_hash.php`, столбец с открытым паролем удалён | `UserRepository`, `AuthController`, `db/migrations` |
| Защита от SQL-инъекций | все запросы через PDO с `?` и `execute([...])`, данные в строку запроса не вставляются | `src/*Repository.php` |
| Права доступа | гость смотрит мероприятия и видит регистрацию с входом; участник подаёт и смотрит свои заявки; администратор управляет заявками. Роль проверяет сервер: `requireLogin` и `requireAdmin` | `Controller` |
| Проверка данных | на сервере (`Validator`) и в браузере (`public/js/validate.js`): те же правила, ошибка под полем | `Validator`, `validate.js` |
| Защита сессии и cookie | cookie с `HttpOnly` и `SameSite=Strict`, новый идентификатор после входа, сессия кончается через 30 минут без действий, при выходе cookie удаляется | `Auth` |
| Защита форм | в каждой форме скрытый токен, сервер отклоняет `post` без него кодом 403 | `Csrf`, `index.php` |
| Подбор пароля | 5 неудачных входов за 10 минут с одного адреса на один логин, потом блокировка | `LoginThrottle`, миграция `003` |
| Заголовки ответа | `X-Frame-Options`, `X-Content-Type-Options`, `Content-Security-Policy` | `index.php` |

Вывод в шаблонах везде через `e()` (экранирование), поэтому теги из полей на странице не выполняются.

## Проверка

До изменений (`01_do_izmenenij.png`): в базе пароли открытым текстом, cookie `PHPSESSID` без флагов, запрос на смену статуса без токена прошёл (302).

После изменений (`02_posle_izmenenij.png`): в базе хеши `$2y$12$...`, у cookie есть `HttpOnly` и `SameSite=Strict`, вход без токена даёт 403.

Остальное проверил в браузере:
- `03_proverka_v_brauzere.png`: неверные данные не отправляются, ошибки под полями;
- `04_gost_perenapravlen_na_vhod.png`: гость открыл «Мои заявки» и попал на вход;
- `05_uchastnik_na_admin_403.png`: участник открыл `/admin` и получил отказ;
- `06_blokirovka_posle_5_popytok.png`: после пяти неверных паролей вход заблокирован.

Попытки инъекции в логин (`' OR '1'='1` и `admin' --`) вход не открыли, ответ 401.

## Результат

Подсистема безопасности работает, пункты задания закрыты.
