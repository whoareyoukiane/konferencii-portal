# Практика 1. Анализ предметной области и требования к ИС

Портал «Конференции.РФ». Выполнил Котлов Арсений Михайлович.

## Предметная область

Организаторы проводят конференции и хотят принимать заявки на участие через сайт, а не по почте и телефону. Участник смотрит список мероприятий, подаёт заявку, выбирает помещение и способ оплаты. Администратор организатора видит все заявки и ведёт их по статусам. После конференции участник может оставить отзыв.

## Назначение системы

Принимать заявки на участие в конференциях и показывать, на каком этапе каждая заявка.

## Пользователи и роли

| Роль | Кто это | Что может |
|---|---|---|
| Гость | Любой посетитель без входа | Смотреть мероприятия, регистрироваться, входить |
| Участник | Зарегистрированный пользователь | Всё, что гость, плюс подавать заявки, смотреть свои заявки, оставлять отзыв |
| Администратор | Сотрудник организатора | Смотреть все заявки, менять статусы, фильтровать список |

## Функциональные требования

Гость:
1. Смотреть список мероприятий (название, дата, место, описание).
2. Зарегистрироваться: логин, почта, телефон, пароль.
3. Войти в аккаунт.

Участник:
1. Войти и выйти.
2. Подать заявку: выбрать мероприятие, помещение и способ оплаты.
3. Видеть список своих заявок и статус каждой.
4. Оставить отзыв с оценкой, когда мероприятие закончилось и заявка завершена.

Администратор:
1. Видеть все заявки с данными участника.
2. Менять статус заявки: новая, назначено, завершено.
3. Фильтровать заявки по статусу и мероприятию.

Правила:
- логин уникальный, 3-20 символов, латиница, цифры и «_»;
- пароль не короче 8 символов;
- телефон в российском формате, почта по шаблону;
- на одно мероприятие у участника одна заявка;
- заявку можно подать только на мероприятие, которое ещё не прошло.

## Нефункциональные требования

| Группа | Требование |
|---|---|
| Адаптивность | Страницы читаются на телефоне 390×844 и на компьютере, без горизонтальной прокрутки |
| Безопасность | Пароли в хешированном виде, запросы к базе с параметрами, права проверяет сервер, защита сессии и форм |
| Производительность | Страница открывается быстро: картинки сжаты, лишних библиотек нет |
| Удобство | Ошибки формы видны рядом с полем, основные действия не дальше двух кликов |
| Надёжность | Данные хранятся в базе, структура меняется через миграции |
